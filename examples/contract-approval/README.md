# Пример: «Согласование договора через несколько отделов»

Живой пакет, собранный ИИ-агентом в воркспейсе и прогнанный до завершения
экземпляра (дрилл 2026-10-18, спека 163). Используй как образец при правке
своих БП: скопируй каталог в `workspace/<твой-slug>/`, поправь `slug` в
`process.yaml` и имена под свою предметную область.

Что демонстрирует:

- **Маршрут через отделы**: регистрация инициатором → юридический отдел →
  финансовый отдел → служба безопасности → утверждение руководителем
  (`approver_resolution: org_unit_head` по полю «Подразделение» документа,
  фолбэк — группа) → итог инициатору (`is_final`).
- **Возвраты на доработку**: `reject_target_task` на каждой согласующей
  ступени + скрипт `on_reject` (`on_reject_note.py`), помечающий карточку.
- **Документы из шаблонов**: «Карточка договора», «Лист согласования»,
  форма команды «Доработка договора»; создание на старте задачи скриптом
  `create_docs.py` с биндингом `on_start` (не `instance_script_bindings` —
  те не действуют на тест-прогоне).
- **Скрипты-гейты**: `validate_contract.py` (обязательные поля),
  `record_legal/finance/sbo.py` (заключение обязано быть внесено),
  `record_decision.py` (решение руководителя → статус договора),
  `finalize.py`.
- **Каталог** «Тип договора» в поле документа (`catalog_reference`).
- **Команда экземпляра** «Вернуть на доработку» с формой и откатом
  (`instance_commands`, bp-уровень — действует после «Применить»).
- **naming/приоритеты/табличный режим** — в `process.yaml`/`table_view.yaml`.

Без `required`-полей в шаблонах, создаваемых на старте (ловушка №2 в
`../docs/process-format.md`); обязательность — скриптами-валидаторами.
